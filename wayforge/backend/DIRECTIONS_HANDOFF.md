# Step 23: Readable Navigator route directions

Your backend's `/api/navigator/:id/route` endpoint now includes **the C++ engine's directions array** alongside the existing `nodes`, `passages`, `metres`, and `minutes` fields. The `/api/published/:id/route` endpoint remains unchanged.

## Install (do not overwrite server.ts)

1. Copy `navigatorAdapter.ts` into `backend/src/services/` (replace existing file).
2. Copy `testDirectionsAdapter.ts` into `backend/src/scripts/`.
3. Copy `checkDirections.mjs` into `backend/`.
4. From `backend/`, run `npx.cmd tsc --noEmit` and `npx.cmd tsx src/scripts/testDirectionsAdapter.ts`.
5. Restart the backend on port 3000, keep Studio running on port 8080, then run `node checkDirections.mjs`.

## Response structure

```
{
  "nodes": ["L1:n1", "L1:n8"],
  "passages": ["walk"],
  "metres": 7.5,
  "minutes": 1,
  "directions": [
    {
      "text": "<generated by C++ wf_cli>",
      "level": "L1",
      "x": 0,
      "y": 2.45,
      "distance": 7.48
    }
  ]
}
```
The example direction text is a placeholder; **no instructions are generated by this adapter**. Every direction is forwarded from `wf_cli` in the order supplied.

`metres` continues to contain the *weighted routing cost* and `minutes` remains a prototype estimate. They are not verified metres or travel times.

## For Shri's Navigator

To display instructions in the website, extend `Route` in `navigator/src/types.ts` with an optional directions property (optional retains compatibility with existing demo data):

```ts
export type RouteDirection = {
  text: string;
  level: string;
  x: number;
  y: number;
  distance: number;
};
// Add within the existing Route type (do NOT replace its other fields):
// directions?: RouteDirection[];
```

Then render `(route.directions ?? []).map(d => d.text)` in the route instruction panel. This frontend display change belongs with Shri, unless you have agreed to help him. The backend does not automatically change the UI.

## Limitations

The single-floor route and building integration has been tested; the multi-floor adapter has only synthetic test coverage until a real published multi-floor `.wfb` is available. A successful backend response with directions does **not** prove that the Navigator UI currently displays them.
